# 벡터화된 북마크 서비스

## 개요
- 사용자: 나 혼자
- 목표: 북마크를 저장할 때 벡터화해 두고, 키워드로 찾은 북마크와 의미가 비슷한 북마크를 함께 볼 수 있게 한다.
- 가장 중요한 것: 경량, 단순

## UX 흐름
- 저장
  - 사용자: 웹사이트에서 북마클릿 실행
  - 북마클릿: 현재 페이지의 링크, 제목, meta description, 본문 앞부분을 추출
  - 북마클릿: 내 Worker 도메인의 팝업 창을 열고 postMessage로 데이터 전달
  - 팝업: 사용자가 메모를 입력하고 저장 (비밀 토큰은 팝업에만 보관)
  - 서버: D1에 텍스트를 먼저 저장 → 임베딩 → D1에 벡터 사본 기록 → Vectorize 삽입
- 찾기
  - 사용자: 웹 UI에서 키워드 검색 (날짜 범위 필터 가능)
  - 사용자: 결과 중 북마크 하나를 선택
  - 서버: 선택한 북마크의 벡터로 유사한 북마크를 조회해서 보여줌
  - 검색어를 임베딩하는 의미 검색은 제공하지 않음 → 찾기 경로에서는 AI를 호출하지 않음
- 관리
  - 삭제만 제공 (D1과 Vectorize에서 함께 삭제)
  - 잘못 저장했다면 삭제한 뒤 다시 저장

## 기능
- 벡터 DB (Vectorize)
- AI 기능은 임베딩 생성에만 사용 (요약, 챗봇 등은 제외)
- 키워드 검색: `LIKE '%검색어%'` (FTS 사용 안 함, 한국어 조사 문제 회피)
  - 검색 대상: 제목, 메모, meta description (본문은 제외)
- 날짜 범위 필터: 키워드 검색에만 적용
- 유사 북마크: Vectorize `queryById` (날짜 필터 없음 → 메타데이터 인덱스 불필요)
- 중복 URL: 저장 거부 (URL에 UNIQUE 제약)

## 기술
- Cloudflare 무료 티어 최대한 활용
  - Workers (TypeScript): API, 팝업 페이지, 웹 UI 제공
  - D1: 원본 저장소 (source of truth)
  - Vectorize: 검색 전용 인덱스 (D1에서 언제든 재구축 가능)
  - Workers AI: `@cf/baai/bge-m3` 임베딩 (1024차원, 다국어)
  - Cron Trigger: 임베딩 대기 항목 재시도
- 프런트엔드: 순수 HTML/JS (프레임워크 없음)
- 인증: 비밀 토큰 1개 (Worker Secret), 요청 헤더로 전달
- 도메인: 보유한 도메인을 Worker에 연결 (다른 서버로 옮겨도 DNS만 바꾸면 북마클릿 유지)
- 상세 설계: `docs/explanation/01-schema-api-design.html`

## 임베딩
- 입력: 제목 + 메모 + 본문 앞부분
- 링크는 벡터에 넣지 않음 (원문 확인 용도로만 저장)
- 입력 길이와 상관없이 벡터는 항상 1024차원 → 본문을 넣어도 저장 용량은 같음
- 본문이 너무 길면 의미가 희석되므로 앞부분만 사용
- 본문은 임베딩 후에도 D1에 보관 (모델을 바꿀 때 재임베딩용)

## 저장 실패 처리
- 텍스트를 D1에 먼저 저장하고 "임베딩 대기" 상태로 표시
- 저장 요청에 응답한 직후 임베딩을 시도하고, 실패하면 Cron Trigger가 대기 항목을 다시 처리
- 상태: `pending`(텍스트만) → `embedded`(D1에 벡터) → `indexed`(Vectorize에도 반영)
- 같은 단계에서 5회 연속 실패하면 재시도를 멈추고 웹 UI에 "임베딩 실패"로 표시
- 같은 로직으로 Vectorize 전체 재구축도 처리

## 이식성과 확장성
- D1에 벡터 사본(BLOB, 북마크당 약 4KB)도 저장
  - D1만 내보내면 북마크 리스트와 벡터를 함께 로컬로 옮길 수 있음
  - Vectorize가 깨지거나 교체할 때 AI 호출 없이 재구축 가능
- 각 행에 임베딩 모델 이름을 기록 (모델을 바꾸면 재임베딩 대상 파악용)
- 벡터 검색 부분은 인터페이스로 분리해서, 나중에 로컬 sqlite-vec, pgvector 등으로 교체할 수 있게 함

## 기본값 (필요하면 변경)
- 날짜: 북마클릿이 보내는 날짜 대신 서버가 저장 시각을 기록
- 시간대: KST 기준
  - D1에는 시간대와 무관한 Unix ms로 저장 (Workers 런타임은 항상 UTC)
  - API 응답은 `+09:00` 문자열로 변환하고, 날짜 필터 `YYYY-MM-DD`는 KST 하루(00:00~23:59)로 해석
- 본문 추출: `main` 또는 `article`, 없으면 `body`의 텍스트에서 앞부분 약 2,000자
- Vectorize 인덱스: cosine 거리, 1024차원 (생성 후 변경 불가)

## 알려진 한계
- Vectorize 무료 티어는 저장 차원 500만 → bge-m3 기준 약 4,880개가 상한
  - 넘으면 Workers Paid(월 $5)로 전환하거나 다른 벡터 저장소로 이동
  - D1에 벡터 원본이 있으므로 이동 작업은 단순함
- `LIKE` 검색은 전체 행을 훑으므로 관련도 순위가 없고, 수만 개 규모에서는 느려질 수 있음
